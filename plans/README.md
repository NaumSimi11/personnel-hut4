## Branch strategy

The advisor never commits to `main`. Each executor works in an isolated git
worktree and branches from the previous plan's branch:
`advisor/001-verification-baseline` ← `advisor/002-navigation-and-robustness` ← … ←
`advisor/007-projects-read-only-panel`. The final branch contains the whole
round; merging it into `main` is the maintainer's decision.

## Findings considered and rejected / deferred

- **localStorage-only persistence, admin-only non-enforcement, manual task completion, single sample request per company, "Ready for day one" with the intro task open** — all documented design decisions in `docs/design-round-01.md`, not defects.
- **Full-re-render architecture** — appropriate at 40 records for a design prototype; not worth replacing.
- **app.js restructuring into modules / immutable state** (audit finding DEBT-01) — deferred: real cost, but doing it mid-round would invalidate every plan's excerpts; revisit after this round lands, with the test suite as the safety net.
- **Focus loss on re-render + tabs keyboard pattern** (audit finding A11Y-01) — deferred to the next design round; needs a focus-restoration approach designed alongside the render model, not bolted on.
- **`btn()` not escaping its text parameter** — all call sites are author-controlled and some intentionally embed HTML; documented in plan 003 as out of scope.
- **Blueprint's richer status lists (Screening/Withdrawn/Rejected)** — documented slice reduction, not drift.
